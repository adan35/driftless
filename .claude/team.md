# Delivery Team — Driftless

Generated by `/bootstrap-team`. The team ships changes to Driftless (immutable double-entry ledger +
card-authorization saga). It is orchestrated by `/deliver`. Every role reads `CLAUDE.md` and respects
the three invariants (Balance, Immutability, Idempotency).

## Roster

| Role | Kind | Path | Use when | Default parallelism |
|------|------|------|----------|---------------------|
| spec-architect | agent | `.claude/agents/spec-architect.md` | No usable spec exists for the task | 1 per spec |
| developer | agent | `.claude/agents/developer.md` | Implementation is required | N (one per independent unit) |
| qa-engineer | agent | `.claude/agents/qa-engineer.md` | Behavior changed and needs verification | N (one per independent unit) |
| code-reviewer | agent | `.claude/agents/code-reviewer.md` | Any non-trivial code change | N (one per independent unit) |
| deliver (PM) | skill | `.claude/skills/deliver/SKILL.md` | Entry point — user invokes `/deliver` | 1 (main context) |

## Standard pipeline (per work unit)
spec-architect (if no spec) → developer → qa-engineer → code-reviewer → loop back on failure.

## Resource-selection rules
- Spec already provided → skip spec-architect.
- Trivial / doc-only change → QA and review optional per risk.
- Independent units → spawn workers in parallel; dependent steps → sequential.
- Anything touching the **ledger core** or the **auth saga** is a sequential, gated change.
- Assign the minimum sufficient team; the PM justifies the composition.

## Shared conventions (all roles)
- Read `CLAUDE.md` first; read the owning spec in `.claude/specs/`.
- The three invariants are correctness, not style — Balance (`SUM(entries) == 0`), Immutability
  (append-only; corrections are new compensating entries), Idempotency (guarded mutating endpoints).
- Money is integer minor units (no float). The `io.driftless.ledger.api` interface is frozen.
  Mutating endpoints take an `Idempotency-Key`. No raw PAN in logs. Use the injected `Clock`.
- Search for existing methods/beans/utilities and reuse before writing new code.
- SLF4J `{}` logging for QA traceability; no `System.out`, no generic logs.
- Never change correct existing business logic; fix incorrect logic deliberately and call it out.
- Never weaken the property-based invariant gate (`LedgerInvariantPropertyTest`).
- Respect module boundaries: dependency direction is inward toward `ledger`/`common`; no cycles.
- Specs → `.claude/specs/NN-*.md`, tests → `.claude/tests/NN-*.md`,
  reviews → `.claude/reviews/NN-*.md` (zero-padded counter from 00).

## Build / test commands
- Test: `.\mvnw.cmd test`  · Full build + gates: `.\mvnw.cmd verify` (macOS/Linux: `./mvnw …`).

## Architecture note
Workers are subagents (leaf executors). The PM is a skill running in the main context because only it
can spawn subagents via `Task`. The central abstraction workers most often touch is the **auth saga**
(`auth` module), which orchestrates `rules` → `ledger`/`HoldView` → `partner-simulator` → capture/
compensating-reversal, every step guarded by `idempotency` and emitting outbox events.
